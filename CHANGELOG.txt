CHANGELOG — Sol-Core Game Starter (the copyable game template)
=====================================================================
Newest entry first. Bullet points only.

2026-09-04 — The reveal decides what the header may show
- The balance no longer moves before the animation shows the result. It used to drop
  ~2 s early — while the coin was still flying, the header already said whether you won.
- BalanceFreezeProvider moved ABOVE DemoProvider in app/page.tsx, so the DEMO balance
  can honour the freeze too. It could not see it before (wrong side of the tree), which
  is why the demo leaked the result even after the real balance stopped doing it.
- SingleBetGame freezes the display the moment the server answers and releases it when
  the view reports the reveal (CoinFlipView.onRevealed). Backstop 3 s + 5 s, so a
  background tab or a broken animation can never freeze the balance for good.
- The win/lose sound and the round-history entry moved to the same moment. Both fired
  on the server answer, so a player with sound on heard the outcome before seeing it.
- ANIMATED_REVEALS in SingleBetGame lists the engines that report their own reveal.
  Every new animation adds its key there, otherwise the balance thaws too early.
- Header: the wallet group (demo badge / connect button / balance) sits on the right,
  next to the menu, instead of centred. Balance and menu belong together, and the
  centred version jumped sideways on connect because badge and balance differ in width.
- New WinToast (design zone): a short win notice under the balance with the amount,
  fades in and leaves by itself. It is a worked EXAMPLE for creators — colour, shape,
  duration and motion are free. Two things are not: it appears only after the reveal
  (never on the server answer), and only on a win — never as an "almost" notice.
- New catalog key in all four languages: win.toast.
- Fed by onLog, which single-bet and session rounds call; live and tournament do not
  log rounds that way and therefore show no notice yet.

2026-09-04 — Coin Flip has its own reveal animation
- New CoinFlipView (design zone) replaces the plain ResultView for the coin-flip engine:
  a coin tosses, flips in 3D and comes to rest on the side the server rolled; the chosen
  side stands above it as a chip, the multiplier / win / roll below.
- Idle frame shows the resting coin plus the engine blurb instead of a bare text block.
- Fairness, the four binding rules (docs/CUSTOMIZE.md):
  * pure function of the outcome — no Math.random, fixed 5 turns plus the half turn that
    leads to details.landed, constant angular speed so the duration never hints at a side;
  * the result nodes stay EMPTY until the coin lands — DevTools, innerText and a screen
    reader learn nothing early;
  * one monotone deceleration that does not know the result — no braking near a winning
    side, no near-miss;
  * win / multiplier / payout are read from the server result, never derived from the roll.
- Geometry and motion live in globals.css ("Coin-Flip-Reveal"); colours come from the theme,
  so NEXT_PUBLIC_ACCENT_COLOR recolours the coin as well.
- prefers-reduced-motion jumps straight to the landed frame.
- New catalog keys (all four languages): coinflip.you, coinflip.idle, coinflip.roll.
  The face letters come from the translated side names, so the coin reads K/Z in German,
  F/P in French and О/Р in Russian.
- This is the first of the engine reveals; the others follow one engine at a time.

2026-09-03 — Every verify link goes to the English verify page
- verifyHref now builds <verifierUrl>/en/verify/<id> (VERIFY_LOCALE = en): one fixed target
  for everything that has to do with verification, in every mechanic.
- Demo rounds link there as well (they used to open the raw JSON demo endpoint);
  FairnessPanel/History/GameMenu drop the apiUrl and demo props they no longer need.

2026-09-03 — "Explore more games" in the game menu
- New link at the foot of the game menu to the platform (https://www.sol-win.net/),
  key menu.moreGames in four languages; PLATFORM_URL in src/lib/links.ts.

2026-09-03 — Game field is square
- The game field above the controls is now a square (aspect-square) on every
  screen size: as tall as it is wide, mobile and desktop alike. Applies to
  SingleBetGame, SessionGame and TournamentGame.
- The inner play area fills the square (h-full instead of a fixed h-28 /
  min-h-[7rem]); ResultView keeps min-h-28 as a floor, SlotGrid and the idle
  text scroll inside the field if they ever exceed it.

2026-09-03 — Game field separated from the controls
- SingleBetGame, SessionGame and TournamentGame now render two blocks instead of
  one card: the game field (animation and result) on top, the controls (stake,
  engine inputs / risk tiers, play or cash-out button, error line) below it.
  A creator can restyle or replace the field without touching the inputs.
- Demo entry button carries its own error state (red button with !, full text
  in title/aria-label) instead of a separate text node: at 360 px that text had
  pushed first the game name and then the wallet button and menu out of view.
- Header title column can no longer collapse to zero width.

2026-09-03 — Header bar, game menu, sound set, max bet at the stake field
- New HeaderBar: game name left, wallet in the middle (connect button; after connecting the
  balance with a dropdown for deposit, withdraw and the platform history link
  https://www.sol-win.net/profile), game menu right.
- GameMenu: wallet row (short address, adapter icon, copy, disconnect), language switch,
  sound toggle, recent rounds (stake · result · value · verify), seed hash button.
- Recent rounds and the seed hash moved from below the game into the menu (rules 6 reworded:
  provably-fair stays reachable from the menu in every mechanic).
- Demo mode starts automatically when no wallet is connected and ends when one connects;
  the demo balance shows as a badge in the header with an exit in its dropdown.
- Max bet hint (BetLimitHint) now sits under the stake input next to MaxBetPick, not at the
  balance (rule 8 reworded: a game limit, not an account limit).
- Sound: scripts/generate-sounds.mjs writes public/sounds/{click,bet,reveal,win,lose,cashout,
  error}.wav (synthesised, <30 KB each); src/lib/sounds.ts exposes useSound() with a toggle
  (default off, stored in localStorage). Wired into SingleBetGame, SessionGame, TournamentGame.
- Popover: shared dropdown primitive (outside click, Escape, ARIA) for balance and menu.
- RoundLog carries the stake (betLamports) for the history rows.
- check:contract: stricter hard-coded-text check — any multi-word JSX text or string literal
  outside the catalog is reported, not only umlauts.
- New catalog keys: menu.*, history.*, money.open, money.amount, demo.open, demo.autoNote.

2026-09-03 — English-first UI, engine texts through the catalog
- All player-visible text is English by default; de/fr/ru follow the language switch.
- Engine descriptions, player hints, field labels and dropdown options moved from
  src/lib/engines.ts (previously hard-coded German) into src/lib/strings.ts as
  `engine.<key>.*` keys. engines.ts now holds catalog keys only; params names,
  values and defaults (the server contract) are unchanged.
- Components resolve engine texts with t(...): SingleBetGame, SessionGame,
  TournamentGame, DemoTournamentGame, LiveGame, LiveCrashGame, EngineControls,
  PvpGame (Hero), DemoPvpGame, DemoDiceDuelGame, DemoDiceProGame.
- Removed the remaining hard-coded German sentences in DemoBar, SessionGame,
  TournamentGame, DemoTournamentGame, LiveCrashGame, LiveGame, LiveResultView,
  CrashCurveView, RouletteBoard, SlotGrid, ResultView and SingleBetGame (keno hint).
- Header shows the configured network (Devnet/Mainnet) instead of a fixed "Devnet".
- <html lang> is "en" (was "de"), matching the default language.
- New catalog keys: engine.* (114), demo.*, session.*, tournament.*, live.*,
  crash.*, roulette.*, slot.*, result.roll, app.defaultGameName — each in all four languages.
