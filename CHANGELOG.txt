CHANGELOG — Sol-Core Game Starter (the copyable game template)
=====================================================================
Newest entry first. Bullet points only.

2026-09-04 — The reels turn out of the position they stand in
- Slot reels (slots-3x3, slots-modular) no longer jump before a spin. Before, every
  Play click nulled the result, the host reset the module to idle, and the strips were
  rebuilt on fixed idle positions — the symbols changed abruptly and only then began to
  roll. Now the flow keeps the last result standing, `reset()` keeps every reel on the
  symbol it stands on, and `play()` plans each reel from its current position: one
  constant cruise speed for every reel and outcome, one fixed ease-out, and the first stop
  time at or after the reel's minimum where the run lands exactly on the server's symbol
  (left to right, ≥ 350 ms / ≥ 250 ms apart). Only the travelled distance differs, in laps.
- Pre-roll: the reels start turning the moment Play is pressed, not when the server has
  answered. New optional `arm({ reducedMotion })` / `disarm()` on the module contract
  (src/lib/reveal.ts) and a `pending` prop on RevealHost: SingleBetGame passes `busy`, the
  module empties its readout and rolls from its position; the outcome's `play()` continues
  that motion without a cut; a failed request settles the reels on the next whole symbol
  without a result. The pre-roll knows no outcome and shows none (rule 16).
- slots-modular reels are now endless virtual strips (cells painted only around the
  window); the server grid is placed at least four cells ahead of every window, so it can
  never appear early. The kit's browser check (scripts/check-reveals.mjs) now also plays
  arm → play, arm → disarm and the reduced-motion pre-roll for every module that has arm().
- Applies to every engine: the last frame stays until the next outcome; no module is reset
  to idle by the flow between rounds. Docs: rule 16 addendum, CUSTOMIZE.md reveal rule 7.

2026-09-04 — Reveal animations for every engine, and nothing shows before they end
- Every engine that plays a round now has a reveal module under src/reveals/<engine>.js:
  coin-flip, dice, limbo, plinko, wheel, keno, scratch, roulette, slots-3x3, slots-modular
  (single bets); mines, towers, hilo, dice-ladder, steps, pump, spin-tower-pro (sessions,
  played STEP BY STEP — only the new step moves); gauntlet (tournament). The PvP dice boards
  keep their interactive layout and tumble a new roll for a moment (lib/dice-reveal.ts)
  before points, Farkle or bank appear. Live engines and pvp-coinflip keep their contract
  views, which already follow the server's reveal window.
- The modules are plain browser JavaScript without a framework — a creator who wants a
  card instead of a coin replaces one file. Contract, registry and loader: src/lib/reveal.ts;
  the host that mounts a module and reports the final frame: components/RevealHost.tsx.
  Fixtures with the exact server shapes: src/reveals/samples/.
- Every module draws its IDLE board from the game's real configuration (engineConfig from
  /api/meta): 16 plinko rows show 17 buckets before the first drop, a 38-pocket roulette
  wheel carries the 00, a 4×4 mines board has 16 tiles, the steps ladder shows the game's
  own rungs and checkpoints. Per round the outcome's own details decide.
- THE FLOWS WAIT. SingleBetGame, SessionGame and TournamentGame hold the server's answer
  (`pending`) until the module reports the final frame (`onRevealed`): only then move the
  HUD multiplier, the sound, the round history, the balance display (freeze released) and
  the win toast. Inputs are locked while a reveal runs. A session step that arrives while the
  previous one is still animating is played after it, never over it. Measured in the built
  app at 360 px (mines, demo mode): 150 ms after a pick every tile is disabled and the HUD
  still reads step 0; after the flip the gem stands, the HUD reads 1.10×; on the mine the
  readout "0.00× Lost" enters the DOM only after the other mines have turned.
- Six rules that are not taste, now written down as rule 16 in docs/RULES.md and checked:
  pure function of the outcome (no Math.random), nothing recognisable early (readout nodes
  EMPTY, not hidden), no near-miss, the winner stands at the end, results only from the
  outcome, no hard-coded text (every label through ctx.text in four languages).
  npm run check:contract section 9 checks the static half (registry ↔ files, no
  Math.random, no network, every text key in the catalog, the flows wired to onRevealed).
  The kit's scripts/check-reveals.mjs plays all 18 modules in Chromium against 90 fixtures
  plus 20 step-by-step sequences and reads the DOM mid-animation.
- A new "Animations" switch in the game menu (lib/motion.ts, stored as sc_motion); off, or
  with the OS set to reduced motion, the final frame appears at once — and everything else
  still waits for it.
- Session replays after a reload: the server now carries progress.multiplierHistory (the
  multiplier after every step call), so a reloaded page replays the round with the right
  figure per step instead of only the current one. Older API builds still work — the
  template writes the history itself while the session runs.
- Removed: components/CoinFlipView.tsx and its CSS — the coin lives in src/reveals/coin-flip.js
  now, with the same flight and the same readout. SlotGrid.tsx stays as a plain component
  (unused by the single-bet flow; the slots modules draw the reels themselves).
- New catalog keys (all four languages): menu.motion*, reveal.* (about 130 keys — the
  module labels: mines, towers, hilo, dice-ladder, steps, pump, spin-tower, gauntlet, plinko,
  dice, limbo, wheel, keno, scratch, roulette, slots). The website's strings mirror is synced.
- Theme tokens for the modules in globals.css (--night, --fg, --accent, --red, --amber,
  --line, --panel, --muted, --faint, --mono): NEXT_PUBLIC_ACCENT_COLOR tints coin, wheel
  and ball as before.

2026-09-04 — The currency approximation reaches every mechanic
- Coin Flip had it; the other twelve mechanics did not. Now every MONEY INPUT in the
  template carries the approximation next to its label: session (mines, towers, pump,
  dice-ladder, steps, spin-tower-pro), live odds, live crash, live drift, PvP, and the
  stake slider of the lobby dialog that PvP, Dice Duel and Dice Pro share.
- Plus the three figures a player actually asks about: the tournament pot, the payout of
  a finished duel (Dice Duel / Dice Pro), and the pot of a demo PvP match.
- WHERE IT DELIBERATELY DOES NOT GO, and why: not into the round history, not into the
  live list of other players' bets, not into the session HUD (pot / secured / cash-out
  side by side), not into the slot win line. Those are places where numbers are compared
  WITH EACH OTHER, not converted — and a second currency in every row of a list is the
  same mistake as printing the max bet twice: it is read once and the page looks
  careless. The balance and the win notification already answer "how much is that" for
  every mechanic.
- FiatHint inherits its label colour now instead of a fixed white. Crash and drift paint
  their labels from their own CSS variables, and a hard-coded white looked like a
  foreign body there.
- Measured at 360 px: session reads "Bet (SOL) ≈ 0,89 €   Max ◎ 2.7611", crash reads
  "STAKE (◎) ≈ 8,88 €   Max ◎ 2.7611" — both on one line, nothing pushed out of frame.
- No new strings, no contract change: check:contract, typecheck, build and the 13 byte-
  mirror checks are green.

2026-09-04 — SOL amounts carry a currency approximation
- Next to every SOL figure the template can now show "≈ 17,40 €" / "≈ $18.90": the
  balance (wallet and demo), the stake label while you type, the result payout and the
  win toast. For a player who has never held crypto, "0.196 ◎" says nothing.
- SOL stays THE number, the approximation stands beside it — settlement is in lamports,
  the Scanner shows SOL, the max bet is in SOL. Replacing the figure would leave a player
  unable to reconcile a round with the verify page.
- The rate never enters a money path: src/lib/fiat.tsx converts for the screen and returns
  a string. Every input stays in SOL. Rule 3 untouched.
- No rate, an implausible one, or one older than 15 minutes ⇒ the line is DROPPED. No
  placeholder, no last known value.
- The rate comes from the platform: /api/price proxies the Gaming API's new
  /api/public/sol-price (Jupiter → CoinGecko → Binance for USD, ECB reference rate for
  EUR, cached 60 s). One request a minute for the whole platform instead of one per
  creator server, and two games can never show two different rates at once.
- Switch (Off / USD / EUR) in the balance panel — in the demo badge as well as the wallet
  balance, because the demo mode starts on its own and for most visitors that IS the
  balance display. Only currencies that have a rate are offered.
- Preselection follows the device language and, being a guess, steps aside when it has no
  rate and the other currency does. A chosen currency never does; "Off" is absolute.
- New in the design zone: Amount.tsx (SOL + approximation), FiatHint.tsx (next to an
  input label), FiatSwitch.tsx (the toggle). Restyle them freely — the two things you may
  not change are in docs/RULES.md rule 15.
- Still SOL-only: the stake fields of session, live, crash, drift and PvP. Own layouts,
  own passes.
- docs/RULES.md: new rule 15, and rule 14 no longer stands in the file twice.
- New catalog keys in all four languages: fiat.show, fiat.off, fiat.note.

2026-09-04 — A comma is a decimal point too
- On a phone whose language uses the comma as decimal separator (most of Europe), a
  fractional stake could not be entered at all: the money fields carry inputMode="decimal"
  and the keyboard offers the DEVICE's separator, with no dot key. "0,5" came back as an
  invalid SOL amount.
- solToLamports accepts a comma now — fixed there, not at the nine input fields, because
  every bet, deposit, withdrawal and PvP stake in every engine goes through that one
  function.
- Thousands grouping is NOT guessed: "1.234,56" and "1,234,567" are rejected rather than
  interpreted. A clear rejection beats a silent factor of 1000 on a money amount.
- Every previously valid input parses to exactly the same lamports as before. The thrown
  message is English now — callers show it straight to the player.

2026-09-04 — The max bet is stated once, and the "Why this limit?" line is gone
- The stake block is now "Bet (SOL) / Max ◎ 2.7611 / [0.01]" — the figure once, nothing
  under the input. BetLimitHint the component is deleted; the file keeps maxBetText and
  MaxBetPick.
- What it costs, stated plainly: the server's reason for the current cap now lives only in
  MaxBetPick's title, and a phone has no hover. Rule 8 says so, and says that bringing the
  explanation back means a surface of its own, never the number twice.
- check:contract follows: MaxBetPick carries the requirement. Found while doing it —
  BalanceBar had been passing the "every stake field shows the max bet" check only because
  the word "BetLimitHint" appeared in one of its comments. It is the money menu and must
  show no max bet at all; it is now excluded on purpose, matched on the deposit/withdraw
  calls rather than on a word in a comment.

2026-09-04 — The header holds its own edge

- Wallet button: "Select Wallet" (165 px) became "Connect" (88 px), so it no longer

2026-09-04 — The reveal decides what the header may show
- The balance no longer moves before the animation shows the result. It used to drop
  ~2 s early — while the coin was still flying, the header already said whether you won.
- BalanceFreezeProvider moved ABOVE DemoProvider in app/page.tsx, so the DEMO balance
  can honour the freeze too. It could not see it before (wrong side of the tree), which
  is why the demo leaked the result even after the real balance stopped doing it.
- SingleBetGame freezes the display the moment the server answers and releases it when
  the view reports the reveal (CoinFlipView.onRevealed). Backstop 3 s + 5 s, so a
  background tab or a broken animation can never freeze the balance for good.
- The win/lose sound and the round-history entry moved to the same moment. Both fired
  on the server answer, so a player with sound on heard the outcome before seeing it.
- ANIMATED_REVEALS in SingleBetGame lists the engines that report their own reveal.
  Every new animation adds its key there, otherwise the balance thaws too early.
- Header: the wallet group (demo badge / connect button / balance) sits on the right,
  next to the menu, instead of centred. Balance and menu belong together, and the
  centred version jumped sideways on connect because badge and balance differ in width.
- New WinToast (design zone): a short win notice under the balance with the amount,
  fades in and leaves by itself. It is a worked EXAMPLE for creators — colour, shape,
  duration and motion are free. Two things are not: it appears only after the reveal
  (never on the server answer), and only on a win — never as an "almost" notice.
- New catalog key in all four languages: win.toast.
- Fed by onLog, which single-bet and session rounds call; live and tournament do not
  log rounds that way and therefore show no notice yet.

2026-09-04 — Coin Flip has its own reveal animation
- New CoinFlipView (design zone) replaces the plain ResultView for the coin-flip engine:
  a coin tosses, flips in 3D and comes to rest on the side the server rolled; the chosen
  side stands above it as a chip, the multiplier / win / roll below.
- Idle frame shows the resting coin plus the engine blurb instead of a bare text block.
- Fairness, the four binding rules (docs/CUSTOMIZE.md):
  * pure function of the outcome — no Math.random, fixed 5 turns plus the half turn that
    leads to details.landed, constant angular speed so the duration never hints at a side;
  * the result nodes stay EMPTY until the coin lands — DevTools, innerText and a screen
    reader learn nothing early;
  * one monotone deceleration that does not know the result — no braking near a winning
    side, no near-miss;
  * win / multiplier / payout are read from the server result, never derived from the roll.
- Geometry and motion live in globals.css ("Coin-Flip-Reveal"); colours come from the theme,
  so NEXT_PUBLIC_ACCENT_COLOR recolours the coin as well.
- prefers-reduced-motion jumps straight to the landed frame.
- New catalog keys (all four languages): coinflip.you, coinflip.idle, coinflip.roll.
  The face letters come from the translated side names, so the coin reads K/Z in German,
  F/P in French and О/Р in Russian.
- This is the first of the engine reveals; the others follow one engine at a time.
